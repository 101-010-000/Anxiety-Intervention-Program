# 角色「脚/鞋 变形」——根因 + 修复（含「膝下粗绑」方案）

> 承接 `_脚部变形_诊断报告.md`（上一版交接：根因未定）。
> 本文 = **结论 + 证据 + 改了什么 + 还能怎么调**。
> 最后更新：2026-09-28 02:10

---

## 0. 一句话结论

**根因：CC_Base 骨架小腿上的 4 根「扭转骨」+ 脚上的「脚趾骨」在 mixamo 动画里【永远不会被驱动】，
而鞋/袜的踝口恰好把 12%~54% 的权重压在这几根骨上 → 这些顶点实际上是「焊在小腿上」。
踝关节一弯（走/跑 40°~90°），鞋底跟脚走、鞋口留在小腿上 → 踝口被拧成肿包。**

**修复（按用户方案）：膝盖以下粗绑 —— 只留「大腿 / 小腿 / 脚」三根骨。
扭转骨权重并给小腿、脚趾骨权重并给脚、踝口按高度在 小腿↔脚 之间过渡。
已生成 15 块修复网格（7 鞋 + 2 类裸脚），写进 9 个角色 prefab，并接进 CharRebuild。**

## 1. 为什么「少绑骨骼」是对的（也是唯一能治本的一刀）

### 1.1 扭转骨 = 小腿骨（数学等价 + 实测）
扭转骨的 localRotation 在动画里【差异 0.0°】（`_扭转骨对比.txt`），
即 `boneWorld(扭转骨) = calfWorld · const`，而 bindpose 里存的也是同一个 `const`，于是

```
M_扭转骨 = boneWorld · bindpose⁻¹ = calfWorld · const · const⁻¹ · calfWorld_bind⁻¹ = M_小腿
```

实测印证（把权重整体并给别的骨看形变）：
**并给小腿 → 1.713 → 1.713（一位不差）**；**并给脚 → 1.713 → 1.324**。

> ⚠ 所以「只把扭转骨并给小腿」这一步**单独做是没有任何效果的**。
> 真正起作用的是后半步：**把踝关节附近的权重划给脚**。这两件事要一起做。

### 1.2 踝部权重剖面（`Shoes_shoes.006_lowsneakers`，网格空间按高度分层）

```
     y 区间           顶点   小腿Calf  Twist01  Twist02   脚Foot  脚趾Toe
     -0.015~-0.003    60      0.0      0.0      0.6     52.1     47.3
      0.052~ 0.063    70      0.0      0.0     17.0     79.6      3.4
      0.063~ 0.074    80      0.0      0.0     29.4     70.0      0.6
      0.085~ 0.096    14      0.0      0.0     54.3     45.5      0.2   ← 鞋口
```
鞋口一半权重在「小腿那边」，而真正的 `CC_BaseCalf` 骨权重是 **0.0** ——
整套鞋/袜的"小腿侧"权重全压在扭转骨上（`001_boots+socks` 的袜筒甚至到 96%）。
脚趾骨同理：坡道修完踝口后，剩下的最后一块畸变**全在脚趾骨**上
（×1.51 的边全在鞋头，两端 `ToeBase 80% vs Foot 62%`）。

### 1.3 修复后的形变量（stretch = 动画中边长 ÷ 绑定姿势边长；一律用同一条【快速跑】量）

| 网格 | 修前 max / >1.5的边 | 只加坡道 | **粗绑（现在）** |
|---|---|---|---|
| 徐夏 `006_lowsneakers` | 1.713 / 7 | 1.512 / 1 | **1.126 / 0** |
| 徐夏 裸脚 `F_body_feet` | 1.551 / 1 | 1.416 / 0 | **1.072 / 0** |
| 王含 `001_boots+socks`（靴+袜） | **3.593 / 60** | 1.888 / 7 | **1.746 / 4** |
| 林溪 `002_sneaker` | 2.082 / 13 | 1.711 / 4 | **1.263 / 0** |
| 张知远 `002_sneaker` | 1.604 / 6 | 1.449 / 0 | 同上（共用同一块网格） |

**另一个更直观的量**：网格相对「刚性绑在自己那只脚」的最大偏差

| 网格 | 修前 | **修后** |
|---|---|---|
| 徐夏 `006_lowsneakers` | 33.4 mm | **6.4 mm** |
| 徐夏 裸脚 | — | 6.8 mm |
| 林溪 `002_sneaker` | — | 56.4 mm（在鞋口 y=0.148） |
| 王含 `001_boots+socks` | — | 142.9 mm（**在袜筒顶 y=0.21，这是故意的** —— 袜筒就该跟小腿走） |

### 1.4 不是重定向的锅（把同一条动画分别放给两套骨架，比世界方向向量）

```
Walk：  CC 踝角 57.0 / 63.8 / 59.5 / … / 48.4    mixamo 51.3 / 57.3 / 53.5 / … / 43.1
        差值恒为 +5.7°（两套骨架 rest 姿势的固定差）
慢跑：  差值恒为 −10.5°；  快速跑： −6.8°~+2.9°；  膝角： 恒为 −32°（CC_Base rest 是微屈腿）
```
**全是"恒定差"、不随时间漂移 → Unity 人形重定向算得是对的**，问题在权重。

### 1.5 上一版的 `TwistBoneDriver` 为什么必然更糟（数字复现）

| 方案 | 徐夏鞋 max |
|---|---|
| 不修 | 1.713 |
| 扭转骨 = Slerp(小腿,脚, 0.3/0.5) | 6.348 |
| 扭转骨 = Slerp(小腿,脚, 0.5/0.8) | 8.678 |
| 扭转骨 = Slerp(小腿,脚, 0.8/1.0) | 10.634 |

原因：**扭转骨的枢轴在小腿中段，不在踝关节**。给它一个"介于小腿和脚之间"的朝向，
等于让脚上的顶点绕小腿中段转几十度 → 整只鞋被甩飞。这条方案正式否决。

## 2. 改了什么（可回滚）

| 东西 | 位置 | 说明 |
|---|---|---|
| 修复网格（15 块） | `assets/02_角色_Character/Meshes/修复权重/*_fix.asset` | 从原 FBX 网格克隆 + 重刷权重 |
| 映射表 | `.../修复权重/_修复映射.txt` | 修复网格 ↔ 原 FBX（供还原 / 下次重修） |
| 写进角色 | 9 个 `角色_URP/*_可动.prefab`：`Shoes_*` 渲染器 + 身体 FBX 里的 `*_feet` | 只换 `sharedMesh` |
| 接线 | `CharRebuild.Attach()` 一行 `FootWeightFix.FixIfShoe(...)` | 以后再跑「重建角色模型」会自动套用（鞋）；裸脚需重跑一次菜单 |
| 工具 | `Assets/Editor/FootWeightFix.cs`（菜单 95~98）、`Assets/Editor/FootSkinProbe.cs`（量化，菜单 90） | |

### 规则（`FootWeightFix.cs` 顶部可调）
```
小腿侧（Calf / CalfTwist01 / CalfTwist02）：
      k = clamp01((y − (踝高 − RAMP_BELOW)) / RAMP)
      (1−k) 的权重 → CC_BaseFoot  （踝关节以下几乎全给脚）
      k     的权重 → CC_BaseCalf  （高筒靴/袜筒才不会脱离腿）
脚趾骨 CC_BaseToeBase  → 全部并给 CC_BaseFoot
大腿扭转骨 ThighTwist01/02 → 并给 CC_BaseThigh

RAMP = 0.16f   跩上 16cm 线性过渡
RAMP_BELOW = 0.01f  坡道从踝下 1cm 起
```
结果（工具每次都会报告）：**修后下肢只用 `CC_BaseCalf.L/R`、`CC_BaseFoot.L/R`** ✓
低帮鞋（鞋口只到踝上 2cm）→ k≈0.05，整只鞋基本刚性跟脚走；
高筒靴/袜筒（踝上 11cm）→ k≈0.85，袜筒仍然跟小腿走。

**回滚**：`Tools/干预项目/修复：还原鞋袜权重（回到原 FBX 网格）`。

## 5. 还没做的 / 需要你确认的

1. **高筒靴的踝口还剩 1.75 的拉伸（4 条边）** —— 这是"靴筒留在小腿、鞋跟脚走"的必然折痕，
   想再压下去只能让靴筒也跟脚走（`RAMP` 调大 / 整只鞋刚性），代价是袜筒和小腿错开。
   `RAMP` 就在 `FootWeightFix.cs` 顶部，改完重跑菜单 ①+② 即可。
2. **腿（`legs_lower/knee/upper`）和裤子没动**：它们身上的扭转骨权重并给小腿是"零变化"，
   所以改了也看不出区别；如果你希望连骨列表一起洗干净，说一声。
3. **如果实际看到的变形比 6mm 大得多**，请给我：哪只脚 / 哪个动作 / 大概什么姿势，
   最好截一张图 —— 现在这个数量级（几毫米）和"畸形"的描述对不上，可能还有第二个原因。
4. 衣服/手那边的形变（`skirt` 15、`sweatshirt` 10、`jacket` 3.7、`shoulders` 2.8）跟脚无关，
   要做的话另开一轮。

## 6. 坑（给下一次的自己）

1. **`AnimationMode` 采样后姿势不保证还原** → 量化工具自己做 Pose 快照/还原；
   分析前先量 rest 姿势。（上次因此把"绑定位自检"量成 3.15m —— 其实是角色站在 x=3.15。）
2. **FBX 网格 `isReadable=0`**：`mesh.vertices` 读出来是空的（`boneWeights` 反而能读）；
   顶点要走 `Mesh.AcquireReadOnlyMeshData`。
3. **`Object.Instantiate(非可读网格)` 在内存里渲不出来** → A/B 必须用落盘的 `.asset`。
4. **`GetComponentInParent` 不看未激活对象**：把邻居 `SetActive(false)` 后，
   下一个角色的 `GetComponentInParent<Animator>()` 会返回 null → 用完要马上放回去。
5. **URP 下临时相机要自带 `UniversalAdditionalCameraData`**，否则 `Camera.Render()` 渲出来是纯背景。
6. **mixamo clip 带 root motion**：机位必须在采样之后再算。
7. **自动触发器要靠域重载**：只丢 `_xxx_trigger.txt` + Ctrl+R **不会跑**，
   必须让脚本重编译（改一下任意 .cs）才会触发 `[InitializeOnLoad]`。本次用了临时文件
   `Assets/Editor/_TriggerTouch.cs`（会话结束已删）。
8. 角色 FBX 里有两个 Animator，**只有离 `SkinnedMeshRenderer` 最近的那个在驱动身体**。
