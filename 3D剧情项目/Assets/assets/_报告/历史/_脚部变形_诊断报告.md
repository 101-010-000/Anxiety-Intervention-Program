## 5. 我试过的修复 + 失败原因（别重犯）

### 5.1 方案：`Assets/Scripts/Visual/TwistBoneDriver.cs`
思路：既然扭转骨从不被驱动，就每帧（LateUpdate）把扭转骨的朝向设成
`Slerp(小腿, 脚, t)` / `Slerp(大腿, 小腿, t)`，把脚踝形变分摊回三根骨。
（这是社区里 "mixamo 动画 + CC_Base 骨架" 的常见偏方。）

**结果：用户实测「所有脚都弯曲了」→ 判定有害，已移除。**
- 已从预览场景移除 9 个实例并保存（`_报告/_清理扭转骨驱动.txt`）
- **脚本文件还在**（头部已加"不要使用"警告），留作参考
- 推测失败原因（供新对话参考）：
  · 直接赋 `transform.rotation`（世界朝向）可能破坏了脚踝链条的父子关系语义；
  · 插值系数/方向可能反了（把脚"扳弯"而不是"分摊"）；
  · 扭转骨本身可能**不应该**被这样驱动（CC_Base 的扭转骨有固定的轴向约定）。

### 5.2 ⚠ 方法学教训（很重要）
- **编辑模式下用 `AnimationMode.SampleAnimationClip` 验证"改了骨头会怎样"是无效的** ——
  `AnimationMode` 处于激活状态时会**每帧把采样姿势写回**，你手动改的骨头会被立刻覆盖。
  我第一次就是这么误判成"没效果"的。
- **正确的验证方式**：进 **Play 模式**，用 `RuntimeInitializeOnLoadMethod` + 协程驱动
  （本项目已有先例：`Assets/Scripts/Game/DoorSmokeDriver.cs`、`AnimPreviewSmokeDriver.cs`、
  `TwistFixABDriver.cs`），渲染/记录后再退出 Play。
- 而且 A/B 必须**同一姿势**：Play 模式里两次渲染之间如果隔了几帧，动画已经走过去了，
  对比就不成立（我做的 `扭转_A_关.png` / `扭转_B_开.png` 就吃了这个亏）。
  建议：`Time.timeScale = 0` 或 `Animator.speed = 0` 冻住后再分别改/渲染。

## 6. 下一步建议的排查顺序（给新对话）

### 6.1 先确认「到底哪些网格在变形」——这一步还没做完
目前**只确认了鞋**（隔离渲染）。但用户说"每个鞋都变形"，
**还没确认裸体脚 `F_body_feet`、裸体腿 `F_body_legs_lower`、裤子/裙 `Bot_*` 是否也变形**。

> 如果**裸体脚也变形** → 那就不是鞋的蒙皮问题，而是**整个脚踝的权重分配**或**重定向姿势本身就错**。

工具已就绪：`Tools/干预项目/渲染：脚部网格隔离（定位肿包是谁）`
（逐块隐藏 / 只留某块，输出 `预览/腿脚/隔离_*.png`）
⚠ 这个工具当前的机位会被**邻居角色挡住**，用前先把其它角色 `SetActive(false)`，或改大机位距离/隐藏邻居。

### 6.2 量「重定向误差」——最可能藏着根因
写个工具，在同一帧同时打印：
- mixamo 源骨架的 `mixamorig:LeftFoot` 的**世界旋转**
- CC_Base 目标骨架的 `CC_BaseFoot.L` 的**世界旋转**
- 以及 `CC_BaseFoot.L` 相对 `CC_BaseCalf.L` 的**相对旋转**

看 Unity 算出来的脚朝向是不是**明显偏了**（比如被多转 90°、或者翻转）。
如果姿势本身就错 → 问题在 **Avatar 的 `humanDescription`**（尤其 `LeftFoot` / `LeftToes` 的旋转），
需要手调 Avatar 配置，而不是改脚本。

### 6.3 检查 `CC_BaseToeBase`（还没查）
鞋有 **15.2%×2** 的权重压在 `CC_BaseToeBase.L/R` 上。如果 ToeBase 的重定向角度不对，脚尖会被拽。
做法同 6.2，把 `ToeBase` 也一起量。

### 6.4 用「同一个角色 + 两套动画」对照
`Assets/assets/03_动作_Animation/Animators/` 里已有 `PC_徐夏_Walk.controller`、`PC_待机_女/男.controller`。
可以做一个最小对照：**同一个角色、同一个 Controller，只换 Motion**，看是不是所有 clip 都一样变形。
（已知答案：新旧动画都一样 → 排除，但可作为"改动后是否真的变好"的基线。）

### 6.5 如果确认是"关节分配"问题，三条出路（按代价）
1. **换成 CC_Base 原生动画**（自带正确的扭转骨曲线）—— 最干净，但可能没有这么多动作
2. **重刷鞋/袜的蒙皮权重**：把 `CC_BaseCalfTwist01/02`（和可选的 `ToeBase`）的权重并到 `CC_BaseFoot`
   —— 3D 软件里做，006 只有 6.2% 最好改，005 有 26.2% 最难
3. **在 Unity 里覆写脚骨**：LateUpdate 里按"小腿朝向 + mixamo 给的脚部相对角"重算 `CC_BaseFoot.L/R`
   —— 等于自己实现一遍脚的重定向（难度高，但不用改美术资源）

## 8. 关键前置知识 / 坑（省得再踩）

1. **两个 Animator**：换 Controller 要改**内层**（`Base_F_body` / `Base_M_body`）那个。
2. **`AnimationMode` 会每帧写回采样姿势** → 编辑模式验证骨骼修改 = 无效。
3. **Unity 会关不关域重载很关键**：`EditorApplication.update` 的 tick ≠ 游戏帧。
   需要等游戏帧时用协程（Play 模式）而不是 tick 计数。
4. **触发器的生效依赖域重载**：改了脚本才会重编译+重载；只改资源不会有域重载，
   这时要么点一下 Unity 窗口按 `Ctrl+R`，要么随便改一个 `.cs` 的注释强制重编译。
5. **改角色 prefab 用 `CharRebuild.cs`**（顶部配置表：外观 / 服装 / 配色 / `Remove=` 身体删减），
   跑 `Tools/干预项目/重建角色模型`。**别手改 prefab 文件。**
6. **`F_shoes.006_lowsneakers` 只被徐夏、组长穿**；如果要换鞋，改 `CharRebuild.cs` 的 `Shoes=` 再重建。
7. 本仓库约定：一次性 Editor 脚本用完要挪到 `额外文件/历史Editor脚本/`；
   报告写 `Assets/assets/_报告/`；临时脚本/dump 写 `额外文件/`。
