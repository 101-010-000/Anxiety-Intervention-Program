# 技术设计：选择题题干清晰化

## 根因 → 对策映射

| 根因 | 对策 |
|---|---|
| 题干无底板，直接压在半透明遮罩+场景上 | 加底板（本方案的核心） |
| 中文_Deng 笔画细、38 号在选项行（44 号级）旁边显小 | 字号 38→44 + Shadow |
| Title 的 Text 挂「Default UI Material」材质覆盖，颜色可能被压住 | `titleLabel.material = null` 回落字体默认材质 |

## 方案对比

### 方案 A：题干加「标题条」底板（★推荐）

给 `Title` 同节点加 `Image` 组件（uGUI 同节点 Image+Text 合法：Image 先画底、Text 后画字；
拖 Title 整体动，用户手调最方便），底板用素材库现有贴图：

- 首选 `assets/05_UI/界面_Panel/面板_标题条.png`（语义就是标题条）；实测不合适再退 `面板_玻璃.png`（左上目标卡同款，配方现成：白×0.82 九宫格 + 深蓝灰字）。
- **文字配色跟随底板明暗**（实现第一步先读贴图平均色再定）：
  - 底板偏浅（大概率，素材库整体是淡蓝风）→ 字用深蓝灰 `#293342`（恰是题干原始色，压在浅底板上对比成立），或目标卡同款 `#293A4A`；
  - 底板偏深 → 字保持 `#CCE3FF` 蓝白。
- 九宫格 border 按贴图像素测（`MainMenuSlices.cs` 有现成测量/切片代码可抄）。
- Text 加 `Shadow`（offset (0,-1)、半透明黑 40%）——细字体的廉价增益；Outline 可选（描边重，默认不加）。
- 尺寸：锚点/位置不动，高度按 44 号字 + 上下各 ~16px padding（约 76），宽度维持 Title 现有矩形。

**为什么不选 B**：B（纯文字加强）治标不治本——根因是「无底板」，亮场景下描边白字照样被场景亮部吃掉。底板是一次性把对比度从「场景决定」变成「自己决定」。

### 方案 B：纯文字加强（最小改动，备选）

只做：字号→44、颜色→纯白、加 Outline+Shadow、清材质覆盖。不新建任何东西，10 分钟完事。
风险：亮度对比仍由背后场景决定，白天宿舍那种亮背景可能还是糊。

### 方案 C：结构改造（否决）

题干挪进对话框区域/复用对话框样式——动 UI 结构、违反「对话框样式铁律」周边，收益为零，不做。

## 实现要点

- **新文件**：`Assets/Editor/ChoiceTitlePlate.cs`（照 `ChoiceTitleColor.cs` 模板：菜单 + 触发器自举 + 异常落盘 `额外文件/错误_*.txt`）。
  - 菜单：`Tools/干预项目/选择题：题干标题加底板（清晰化）`；触发器 `Assets/_choicetitleplate_trigger.txt`。
- **幂等规则**：Title 已有 Image 且 sprite 一致 → 只补缺（Shadow/材质覆盖/字号检查），绝不覆盖用户手调的锚点/尺寸/颜色。
- **运行时零改动**：`ChoicePanel.cs` 的 `Open()` 只写 `titleLabel.text`，不碰 Image/颜色 → 无需改运行时代码。

  存 `assets/_报告/预览/场景/选择题题干_修后.png`。（若编辑器渲染面板子树有困难，退级方案：让用户 Play 一章截图验收。）

## 实施结果（v3，2026-09-30 落地）

与原设计的偏差（都有实证原因）：

1. **底板高度自适应**：翻剧本发现题干不是短标题，是 15~91 字的说明段（最长 91 字 ≈4 行），
   固定高度方案作废 → 题干带挂 `VerticalLayoutGroup`（内边距 30/16）+ `ContentSizeFitter(垂直=PreferredSize)`，
   文字排几行带就长到几行。
2. **字号 40（不是 44）**：44 号让最长题干排 5 行、底边离选项区只剩十几像素；40 号 4 行收住，余 ~35px。
3. **结构从"Title 挂 Image"改为「题干带」容器**（实施中两版被推翻的实录）：
   - v1 底板做 Title 的子节点 → uGUI 父 Graphic 先画、子后画，**底板把文字盖住了**（预览实证）；
   - v2 想把 Image 加到 Title 本体 → 实测该节点 `AddComponent<Image>()` **恒返回 null**（组件清单健康、
     activeSelf=True，怪癖不纠缠）；
   - v3 全部用构造器建新节点（可靠）：`Panel/题干带(新容器) ← 题干底板(sibling 0 垫底, stretch+外扩)
     + Title(原样挪入)`——`ChoicePanel.titleLabel`/字号/颜色接线零改动，文字与底板是兄弟节点、
     sibling 顺序天然保证文字在上。选项行"行根挂图+文字做子节点"是同款结构。
4. **颜色 #CCE3FF→#1B2C42（墨蓝）**：底板是半透明中蓝（均值 #77B9F1），深字对比暗场景 ~4:1、
   亮场景 ~7:1；白字在亮场景会随底板变亮失效。
5. 顺带澄清一个历史疑案：上次配色报告提示的「Default UI Material 材质覆盖」是 uGUI `Text.material`
   属性运行时回落字体默认材质的假象，序列化 m_Material 实际为空，从未有覆盖。
6. 原"Text 加 Shadow"一条在 v3 落地时**省略**：墨蓝粗体字压浅蓝底板对比已足够（质检通过），
   再叠投影反而发糊。design 方案 A 原文有此项，特此记偏差。

验证记录：报告 `assets/_报告/_选择题题干清晰化.txt`；预览两张（真实场景/亮背景）目检通过；
幂等重跑走"已接线→只核对"路径无副作用；场景节点按 Unity YAML 转义形态（大写 \uXXXX 带引号）
字节级确认落盘 ×1。**待用户 Play 验收**。
