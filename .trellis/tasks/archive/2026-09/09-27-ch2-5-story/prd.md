# 第2-5章剧情制作：复用第一章GUI与UI模板

## Goal

按**最新版剧本 `项目文档/剧本更新.docx`**（提取稿 `额外文件/剧本更新_extract.txt`，★ 唯一正文权威源）制作第 2–5 章的完整可玩剧情；
旧版 `剧本.docx`（提取稿 `剧本_extract.txt`）仅作对照参考，两者冲突时一律以更新版为准。
样式与体验与第一章完全一致：**第一章已搭好的 UI 结构、贴图、布局、交互流程原样复用，不新建任何 UI 界面**；
第一章没有的能力（黑屏转场、手机换聊天对象等）只做最小功能扩展，且必须复用现有控件与素材；
确实缺的素材（其他聊天对象头像等）按用户约定**先用占位素材**。

### 缺口（本任务要做的事）

1. **章节数据**：`Assets/数据/剧情/第2章.json` ~ `第5章.json`（沿用第 1 章八种步骤格式 card/nar/dlg/mon/interact/walk/choice/end；微信台词 s 带"（微信）"）。
2. **多章加载**：场景仅 1 个 StoryRunner（绑第 1 章）。需让任意章能被主菜单选中后开跑。
3. **交互点归属**：`StoryRunner.FindFree()` 全场景找第一个未消费交互点，多章交互点并存会拿错 → 需按章过滤。
4. **黑屏转场**：更新版剧本多处要求"黑屏/刷新转场"（第 3 章进办公室、第 4 章动作替代、第 5 章宿舍→图书馆等）→ 需要新步骤类型 `fade`（复用 BlackFade + 传送玩家，不建新 UI）。
5. **手机换聊天对象**：PhoneChatUI 标题固定"林溪"，第 2 章要切 李同学→林溪，第 4 章要 班群+学姐 → 需要 `SetContact()` 能力 + 缺失头像用占位。
6. **场景接线**：每章 StoryRunner 节点（绑 json/起点/UI 共享引用）+ 各章锚点/触发点 → 按仓库约定用 Editor 工具 + 手动菜单项搭（不手写场景文件、不用自动触发器）。
7. **运行自检**：参数化到第 2–5 章，每章跑通出报告。

## Requirements

### R1 章节数据（第 2–5 章 json）
- **正文一律以 `剧本更新.docx`（`剧本更新_extract.txt`）为准**。更新版相对旧版不只是加演出注记，还有正文增删，录入时照更新版：
  - 第3章新增台词：林溪「你先去点饭，我找个座位！」/ 徐夏「好」/ 独白「去看看有什么饭吧......」；
  - 第4章新增引导句：「点开通知看看吧。」「得赶紧看看复习资料了......资料就在桌子上。」；
  - 第5章新增引导句：「回到自己的位置上吧。」「还是去图书馆好了。」（替换原"落荒而逃地来到了图书馆"）；
  - 删改的走位/动作句（第4章删林溪进场揣测句、第5章删"并肩往食堂走去"、蹲身改"她看着椅子上的徐夏"、拍肩动作视实现删）照更新版处理。
- 剧本台词逐句录入，不删减正文（更新版自己删掉的除外）；旁白/独白/对话按第 1 章的 nar/mon/dlg 三语态映射。
- 微信台词 `s` 带"（微信）"后缀（徐夏（微信）/林溪（微信）/李同学（微信）/学姐（微信）/班群（通知）），由现有 PhoneChatUI 路径展示。
- 每章 4 道干预题（①自我焦虑记录 ②补鼓励 ③新认知 ④未来自我创作）按更新版原文录入 head/body；第 4 章 ③ 的题干按剧本用"环境带来的新认知"表述。
- 剧本笔误沿用第 1 章处理方式：json 里写修正版（如"越在意结果"），报告里注明。
- 更新版"插入玩家行为/玩家行动"注记落成 interact/walk 步骤（各章清单见 design.md D3）；"做不了就黑屏替代"的动作落成 fade 步骤（见 R3）。
- **两处黄亮"外人对话"（第3章 L273 隔壁桌、第4章 L405 舍友抱怨）更新版仍是待补充状态**：内容等用户提供后录入，先按预留方案占位——dlg 说话人写"旁人甲/旁人乙"（背景人声，无名牌实体、无 3D 模型），占位文案用一句中性过渡（如"（隔壁桌的闲聊）"）或先不插步骤，用户补稿后再加上；实现时不阻塞。
- 贴纸：剧本里的 `比心_720.png` / `献花_720.png` / `加油_720.png` 对应现有 [比心][鲜花][加油] 贴纸，台词整句写标签。

### R2 多章加载与场景接线
- 主菜单选第 N 章进 Game 场景 → 对应章节的 StoryRunner 自动开跑，其余章节 runner 静默。
- 全部剧情 UI（对话/选择题/手机/WalkHint/结束卡/黑幕）仍用 `UI交互` 下同一套节点，多章共享，一处不改样式。
- 每章有独立 startAnchor（起点）与黑屏转场落点（fade 目标），摆在对应 Loc 内合理位置。
- 摆位通过 `Assets/Editor/` 工具 + 手动菜单项完成；**禁止自动触发器**（AGENTS 已踩坑定稿）；**禁止手写场景 YAML**。
- 工具幂等：重复执行不破坏用户随后在场景里的手改（参照第一章归档教训）。

### R3 黑屏转场步骤（fade）
- 新步骤类型 `fade`：BlackFade 淡入 → 传送玩家到目标锚点（CharacterController 先关再开，照抄门口传送的坑）→ 淡出 → 继续。
- 目标锚点在 json 里按名字引用（如 `"to": "第3章_办公室内"`），场景里放同名 Transform 子节点。
- 不新建任何 UI 节点；BlackFade 的层级/样式不动。

### R4 手机聊天换联系人
- `PhoneChatUI` 增加 `SetContact(名称)`：换标题文字 + 清空聊天流（换群/换人时必然新开一段）。
- 联系人切换时机由 json 驱动（微信段开始前的旁白/或新字段），默认沿用现有 Show() 行为。
- 李同学/学姐/班群没有头像素材：**占位方案**——左右头像先用现有贴图（林溪/徐夏头像当通用头像），标题文字换为实际联系人名；不生成、不修改任何素材文件。后续用户给了新头像再换（引用字段化预留）。
- 素材样式与比例铁律继续生效：不改布局常量、不改进气泡判定逻辑（speaker 含"徐夏"→右侧蓝泡）。

### R5 交互点章节归属
- `StoryInteractable` 增加章节标记（如 `chapterTag` int），`FindFree()` 只取本章且未消费的交互点。
- 第 1 章现有 TalkPoint/BumpPoint 标记为 1，行为不变；第 1 章自检必须照常通过（回归）。

### R6 运行自检
- 自检工具参数化：可为第 1–5 章各自跑「真进 Play 跑完全部步骤」并出报告（沿用 `assets/_报告/_第一章剧情运行自检.txt` 风格，每章一份）。
- fade 步骤在自检里照常执行（DebugAdvance 推进路径覆盖新状态）。

### R7 保存/进度兼容
- `GameProgress`/`SaveSystem` 不改结构；第 2–5 章通关后 MarkCompleted 正常解锁下一章（现有逻辑天然支持）。
- 选择题记录 `story.choice.<题号>` 命名空间按章隔离（如 `story.choice.ch2.0`），避免覆盖第 1 章记录；主菜单内容概览页 5 章页签照常显示（现有实现按章读取）。
  - ⚠ 若现读取键名为固定格式需在实现前核对 `MainMenuUI` 概览页读取逻辑，保持一致。

### 非目标（明确不做）
- 不做各章时间/氛围滤镜（ScenePostFx 章节氛围）——后置增强，本次最多留TODO。
- 不做新 UI 界面/新贴图/新字体；不为李同学、学姐做 3D 模型。
- 不改第一章任何 UI 样式、不动 `对话/对话框/名字/对话内容`（冻结定稿）。
- 不做考场（第 5 章开头）场景，按报告跳过/复用黑屏转场。
